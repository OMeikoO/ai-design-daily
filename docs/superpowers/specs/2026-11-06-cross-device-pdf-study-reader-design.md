# 跨设备 PDF 学习阅读器 · 设计文档

日期：2026-11-06
状态：已确认（用户选择方案 A + 文本/PDF 双模式）

## 1. 目标与场景

- 用户备考软考高项，需要利用碎片化时间阅读 PDF 资料（重点考点汇总、案例、论文专题）。
- **公司电脑 + 家里电脑** 两台设备，通过 **Trae 打开同一个远程沙箱工作区**。
- 核心诉求：**标注与阅读记录跨设备实时互通**；支持**添加/删除图书**；数据处理方式最便捷。

## 2. 方案选型

选定：**沙箱常驻轻量服务 + 数据即工作区文件**（方案 A）。

- 互通原理：数据只有一份存于沙箱工作区，两台电脑经 Trae 预览访问同一服务地址 → 天然一致，零手动同步。
- 备选方案 B（静态页+手动导入导出）被否：换设备需手动操作，不便捷。
- 备选方案 C（本地文件夹+云盘同步）被否：依赖第三方云盘配置，不符合"通过 Trae 打通"。

## 3. 架构

```
公司电脑 ──┐                    ┌── 家里电脑
           └→ Trae 预览同一地址 ─┘
                      ▼
        Trae 远程沙箱（端口 8787，server.py 常驻）
         ├─ 托管前端 index.html + libs/（pdf.js）
         ├─ REST API：书架 / 标注 / 进度 / 搜索
         └─ PDF 按 HTTP Range 分段加载
                      ▼
        data/（纯文件，git 自动备份）
          ├─ books.json          书目索引
          ├─ books/*.pdf         图书文件
          ├─ texts/<id>.json     提取的结构化章节文本
          └─ state/<id>.json     阅读进度 + 标注
```

## 4. 功能清单

1. **书架**：图书列表（进度百分比、文本提取状态）、上传 PDF（后台自动提取文本）、删除图书（连带其数据）。
2. **PDF 精读模式**：荧光笔 4 色高亮、下划线、便签、画笔、内置目录导航、缩放、双页、暗色主题（沿用既有能力，存储改到服务端）。
3. **文本速读模式**：结构化章节目录、秒开、选中文字即荧光笔标注/便签、全文搜索。
4. **标注管理**：侧栏统一列表（含模式徽标）、点击跳转原文、逐条删除、**Undo 撤回最近一条标注**（会话栈，最多 20 条）。
5. **同步**：翻页/标注即时 PUT 到服务端；进度按 updatedAt 新者胜合并；窗口聚焦/60s 轮询拉取远端变化。

## 5. 数据格式

state/<id>.json 示例：

```json
{
  "bookId": "b001",
  "updatedAt": "ISO8601",
  "progress": {
    "pdf":  { "lastPage": 100, "zoom": 1.2, "double": false, "updatedAt": "..." },
    "text": { "chapterIdx": 5, "ratio": 0.4, "updatedAt": "..." }
  },
  "annotations": [
    { "id": "a1", "mode": "pdf",  "page": 12, "type": "highlight",
      "rects": [{"x":0.1,"y":0.2,"w":0.5,"h":0.02}], "text": "...", "color": "#ffe066" },
    { "id": "a2", "mode": "text", "chapterIdx": 5, "start": 100, "end": 130,
      "text": "...", "prefix": "...", "suffix": "...", "color": "#ffe066" },
    { "id": "a3", "mode": "pdf",  "page": 15, "type": "note", "x": 0.5, "y": 0.3, "content": "..." }
  ]
}
```

- 文本标注锚点：章节内字符偏移 + prefix/suffix 上下文，重渲染时优先按偏移、失配时按上下文模糊定位。
- 所有写操作：细粒度（单条标注增/改/删、进度合并），服务端内存锁 + 临时文件原子替换，降低两设备并发冲突。
- 书文件流式加载：HTTP Range + 206，前端 PDF.js 自动按需分段拉取。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/books | 书目列表（含进度摘要、提取状态） |
| POST | /api/books | 上传 PDF（multipart），后台线程提取文本 |
| DELETE | /api/books/{id} | 删书（文件+文本+状态全清） |
| GET | /api/books/{id}/file | PDF 流（Range 支持） |
| GET | /api/books/{id}/texts | 结构化章节文本 |
| GET | /api/books/{id}/state | 进度+标注 |
| PUT | /api/books/{id}/progress | 进度合并（updatedAt 新者胜） |
| POST | /api/books/{id}/annotations | 新增标注，服务端分配 id |
| PUT | /api/books/{id}/annotations/{aid} | 修改标注（便签内容等） |
| DELETE | /api/books/{id}/annotations/{aid} | 删除标注 |
| GET | /api/search?q=&book= | 全文搜索（跨书，返回章节/页码/摘要） |

## 7. 文本提取

- pypdf 读取目录树（过滤 OLE_LINK 噪声）→ 章节结构（标题/起始页/层级）。
- 逐页提取文本，清洗每页重复的页眉页脚水印（"91过软考教育学院内部资料"等）。
- 章节文本 = 起始页到下一章节起始页的正文拼接；提取失败的书仅影响文本模式，PDF 模式不受影响。
- 新上传的书由服务端后台线程执行同一提取器，前端轮询状态。

## 8. 可靠性

- **保活**：定时任务（每 30 分钟）curl 探活，失败则以 nohup 拉起 server.py。
- **备份**：keepalive 顺带检查 git 脏数据，每至多 6 小时自动 commit 一次 data/。
- **并发**：标注级细粒度操作 + 原子写；进度双端合并策略明确（新者胜）。
- **沙箱休眠**：服务随沙箱起落，定时任务唤醒后自动恢复；期间无数据丢失风险（数据全在文件）。
